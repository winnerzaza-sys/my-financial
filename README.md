# แชทรายรับ–รายจ่าย

PWA ภาษาไทยสำหรับบันทึกรายการจากแชทและสลิป ดูยอดตามช่วงเวลา และตั้งงบรายเดือน เปิดใช้งานบนเครื่องเดียวได้ทันทีด้วย IndexedDB เมื่อเชื่อม Supabase ให้เข้าสู่ระบบบัญชีเดียวกันบนแต่ละเครื่อง

## รันบน Windows

ใช้ Node.js 22.12 ขึ้นไป แล้วเปิด PowerShell ในโฟลเดอร์โปรเจกต์

```powershell
npm ci
npm run dev
```

เปิด URL ที่ Vite แสดง เพื่อทดสอบไฟล์ production และการเปิดซ้ำออฟไลน์ ให้ใช้คำสั่งชุดนี้

```powershell
npm run typecheck
npm test
npm run build
npm run preview
```

สำหรับ iPhone ใช้เว็บ production ที่ให้บริการผ่าน HTTPS และเปิดใน Safari จากนั้นเลือก **แชร์ → เพิ่มไปยังหน้าจอโฮม** เปิดแอปสักครั้งขณะออนไลน์และรอให้หน้าโหลดเสร็จ จึงลองปิดเน็ตและเปิดซ้ำ การเปิดผ่าน HTTP จาก IP ของเครื่องในเครือข่ายไม่ให้สิทธิใช้ WebGPU และ Service Worker แบบเดียวกับ HTTPS หรือ localhost

## Phase 1 เก็บในเครื่องและย้ายข้อมูลด้วยไฟล์

Phase 1 ใช้ IndexedDB ของเบราว์เซอร์และ URL ที่เปิดแอป ใช้งานได้ทันทีโดยไม่ต้องสร้างบัญชีหรือกำหนดค่า Supabase

- กด **ใช้บนเครื่องนี้ → ดาวน์โหลดไฟล์ย้ายข้อมูล** เพื่อเก็บธุรกรรม แชท และงบเป็น JSON ที่มีเลขเวอร์ชันและรหัสรายการเดิม เก็บไฟล์นี้ไว้ในที่ส่วนตัว
- กด **นำเข้าไฟล์ลงเครื่องนี้** เพื่อกู้ข้อมูลหรือย้ายไปอีกเบราว์เซอร์ แอปเพิ่มข้อมูลด้วยรหัสเดิมและเก็บค่าที่มีในปลายทางสำหรับรายการที่มีรหัสตรงกัน
- รูปสลิปต้นฉบับ ร่าง และประวัติการแก้ไขอยู่เฉพาะในโปรไฟล์ที่สร้าง ประวัติการแก้ไขดาวน์โหลดได้จากปุ่มแยก

## Phase 2 เปิดใช้การซิงก์

1. สร้างโปรเจกต์ Supabase สำหรับทดสอบ และเปิดการสมัครผ่านอีเมลและรหัสผ่านใน Authentication
2. ลง migration ใน [supabase/migrations](supabase/migrations) ผ่าน SQL Editor ของโปรเจกต์ทดสอบ หรือใช้ Supabase CLI ที่ผูกกับโปรเจกต์นั้นแล้ว
3. ใช้ `Copy-Item .env.example .env.local` ตั้ง `VITE_ENABLE_CLOUD_SYNC=true` แล้วกรอก `VITE_SUPABASE_URL` และ `VITE_SUPABASE_PUBLISHABLE_KEY` จาก Supabase ใช้ publishable key สำหรับเว็บเท่านั้น
4. เปิด Vite ใหม่ หรือ build ใหม่หลังแก้ env กดสถานะมุมขวาบนเพื่อสมัครหรือเข้าสู่ระบบ กด **นำเข้าไฟล์เข้าบัญชีนี้** แล้วเลือกไฟล์ย้ายข้อมูลจาก Phase 1 แอปจะใส่ข้อมูลในคิวซิงก์ของบัญชีนั้น ตรวจสถานะให้ซิงก์สำเร็จ หากใช้ URL และเบราว์เซอร์เดิม สามารถกด **นำเข้าข้อมูลก่อนเข้าสู่ระบบ** ได้โดยตรง
5. ตั้ง Site URL และ Redirect URLs ใน Supabase ให้ตรงกับ URL ที่ใช้ยืนยันอีเมล

รายการ ข้อความ และงบอยู่ในฐานข้อมูลแยกตามบัญชี และซิงก์ผ่าน RPC ที่ตรวจเจ้าของ ฐานบนเครื่องเก็บภาพสลิปต้นฉบับ ร่าง และประวัติการแก้ไข ข้อมูลสามส่วนนี้อยู่ในโปรไฟล์ที่สร้างและไม่ถูกส่งขึ้น Supabase เมื่อเกิดความขัดแย้ง ให้เปิดสถานะซิงก์และเปรียบเทียบข้อมูลก่อนเลือก ถ้าเลือกข้อมูลอีกเครื่อง การแก้ไขในคิวที่อาศัยชุดเดียวกันจะถูกนำออกด้วย

## Qwen และ OCR

- Qwen ใช้ `onnx-community/Qwen3-1.7B-ONNX` รุ่น `q4f16` ผ่าน Transformers.js และ WebGPU โหลดครั้งแรกเมื่อส่งข้อความ หากเปิดโมเดลไม่ได้หรือผลไม่ผ่านการตรวจ แอปใช้ตัวอ่านภาษาไทยพื้นฐานร่วมกับแบบฟอร์ม กำหนด `VITE_ENABLE_QWEN=false` เพื่อทดสอบเส้นทางนี้โดยตรง
- OCR ใช้ Tesseract.js ใน Worker และพจนานุกรมไทยกับอังกฤษ เมื่อแนบสลิปต้องเลือกทิศทางเงินและตรวจข้อมูลก่อนบันทึก หากอ่านยอดไม่ชัด แอปจะเว้นยอดไว้ให้กรอก
- ค่าเริ่มต้นโหลดโปรแกรมที่ระบุเวอร์ชันและไฟล์โมเดลจาก CDN/Hugging Face คำสั่งประมวลผลข้อความและรูปอยู่ในเบราว์เซอร์ กำหนด URL ใน `.env.example` ถ้าโฮสต์ runtime หรือไฟล์ OCR เอง การประมวลผลออฟไลน์ขึ้นกับไฟล์ที่เบราว์เซอร์เก็บไว้ ส่วนหน้าแอปและการกรอกเองใช้แคชของ PWA
- ทดสอบ Qwen แยก Safari, Home Screen และ Chrome/Edge เดสก์ท็อป จับเวลาเปิดโมเดลครั้งแรกและครั้งถัดไป ทดสอบ OCR ด้วยสลิปจริงที่ปิดข้อมูลส่วนตัวแล้วและทดสอบรูปที่อ่านไม่ได้

## ตรวจรับสองเครื่อง

1. ใช้บัญชีเดียวกันบนสองเบราว์เซอร์ บันทึก “วันนี้เพื่อนโอนค่าข้าวมาให้ 100 บาท และซื้อขนมไป 50 บาท” ให้เห็นสองรายการและสุทธิ +50 แก้ขนมเป็น 60 ให้เห็น +40 ทั้งคู่
2. พิมพ์ “ซื้อขนม” รีเฟรชในห้องเดิม ตอบ “35” ให้ได้รายการเดียว แนบสลิปที่มีเลขอ้างอิงเดิมให้เห็นรายการเดิมเพื่อเปรียบเทียบ
3. ตัดเน็ตเครื่องแรกแล้วบันทึกชุดรายการ แก้รายการเดียวกันต่างเครื่องแล้วต่อเน็ต ตรวจว่าคิวบันทึกครั้งเดียว เห็นความขัดแย้ง และเลือกผลได้ รวมกรณีอีกเครื่องลบไปแล้ว
4. ทดลองด้วยบัญชีอื่นและยืนยันว่าไม่เห็นข้อมูลบัญชีแรก ลองย้ายวันที่ข้ามเดือนและตรวจยอด/งบของทั้งสองช่วง ลองลบและย้อนกลับ แล้วตรวจข้อมูลหลังซิงก์
5. เลือก “AI ตีความผิด” ตอนแก้ ตรวจประวัติและไฟล์ JSON บนเครื่องเดิม และตรวจว่ารูปต้นฉบับกับประวัติการแก้ไขไม่ปรากฏบนอีกเครื่อง
6. เปิดจาก Home Screen บน iPhone ตรวจไอคอน เลย์เอาต์ และการบันทึกผ่านฟอร์มทั้งตอนออนไลน์และออฟไลน์

## ผลตรวจใน workspace

| การตรวจ | ผล |
|---|---|
| TypeScript, Vitest, Vite production | ผ่าน `npm run typecheck`, `npm test` 19 กรณี และ `npm run build` |
| Chromium เดสก์ท็อปและ viewport มือถือ 440 px | ผ่านข้อความหลายรายการ, ยอด +50 เป็น +40 หลังแก้, ตอบร่างหลังรีเฟรช, แผงประวัติ AI และกรอกเองเมื่อออฟไลน์ระหว่างเปิดแอป |
| PostgreSQL แบบฝังตัว | ผ่านการลง migration, ส่ง operation ซ้ำ, cursor, conflict, RLS แยกเจ้าของ และการปฏิเสธลิงก์ข้ามเจ้าของแบบ atomic และการย้าย JSON จาก IndexedDB ไป PostgreSQL ด้วยรหัสเดิม |
| PWA | ตรวจไฟล์ app shell 40 ไฟล์และทดสอบทางเลือกเมื่อเครือข่ายหยุดด้วย Cache จำลอง |
| รอตรวจในสภาพใช้งานจริง | Windows, Supabase จริงสองเครื่อง, Qwen/WebGPU และเวลาตอบสนอง, OCR บนสลิปไทยจริง และการเปิดซ้ำจาก Home Screen บน iPhone |

โปรเจกต์ใช้ไอคอนน้องเหรียญที่ทำขึ้นสำหรับ build นี้ เนื่องจากสภาพแวดล้อมดาวน์โหลดไฟล์อ้างอิงไม่ได้
